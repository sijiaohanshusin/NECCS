# 2025 年综测参考题——现有工程检验说明

工程：`CompetitionBase_MDK`  
主程序：`User/competition_main.c`  
题目应用层：`User/exam_2025.c`、`User/exam_2025.h`  
汉字显示：`Drivers/BSP/COMPETITION/comp_hanzi.c/.h`

## 一、结论

七项功能均能在原有引脚和原有底层驱动上实现，没有重新分配引脚，也没有新写 GPIO、串口、LCD、QSPI 等底层驱动。

- Keil 工程已编译：**0 Error，0 Warning**。
- 已生成：`Output/atk_h750.hex`。
- 题目写的是 OLED，当前硬件是正点原子 4.3 寸 **TFTLCD**。程序已在 TFTLCD 上实现相同文字显示；若现场规则强制要求物理 OLED，才需要另接 OLED。
- 外接灯板和按键板尚未连接时，相关代码仍能编译，但无法完成实物动作验证。

## 二、只使用的既定引脚

| 逻辑名称 | 既定引脚 | 实物位置/说明 | 本题用途 |
|---|---:|---|---|
| LED1 | PB14 | P5-3 | 灯 1 |
| LED2 | PB15 | P5-5 | 灯 2 |
| LED3 | PA3 | P5-7 | 灯 3 |
| LED4 | PC3 | P5-9 | 灯 4 |
| 按键 1 | PA1 | 板载 KEY0 | 松开后启动流水灯 |
| 按键 2 | PA15 | 板载 KEY1 | 发送 `key2` |
| 按键 3 | PC0 | P5-11，外接 | `aa += 0.5` |
| 按键 4 | PA12 | P5-13，外接 | `aa -= 0.5` |
| 串口 TX/RX | PA9/PA10 | 板载 USB_UART/CH340 | 与上位机通信，115200 8N1 |
| 非易失存储 | 板载 16MB QSPI | 应用保留末尾 1KB | 保存 `aa` |
| 显示屏 | 原有 FMC LCD 接口 | 4.3 寸 TFTLCD | 显示题目、状态和 `aa` |

既定但本题没有调用的资源仍保持不变：独立 PWM 为 PA11/P5-14/TIM1_CH4；MAX7219 为 PB12、PE0、PA2。

## 三、七题逐项对应

1. 上电立即写 LED 掩码 `0x05`（灯 1、3），非阻塞计时 30000 ms 后写 `0x0F`（全亮）。
2. 按键 1 按下时只置位“等待松开”标志；检测到松开后先全灭，再每 500 ms 依次形成 `0001 → 0011 → 0111 → 1111`。
3. TFTLCD 显示 **st测评题**。其中 ASCII 使用原 LCD 字库，三个汉字使用新增 16×16 子集字库。
4. 按键 2 发送 `key2\r\n`，同时显示 **发送成功**。
5. 收到 `st` 后发送 `st is ok\r\n`。兼容直接发送两个字符 `st`，也兼容 `st` 后加 CRLF。
6. `aa` 内部采用“扩大 10 倍的有符号整数”保存：0.5 对应整数 5。按键 3 加 5，按键 4 减 5，每次刷新屏幕、保存并发送 `aa=x.x`。
7. 每次改变 `aa` 都写入 QSPI 保留区。记录含魔数、版本、数值、校验和与反码；重新上电校验通过后恢复，首次使用或记录无效时显示 0.0。

## 四、附加综合检验条件

- `aa == 0.0` 时板载蜂鸣器持续响；`aa != 0.0` 时立即关闭。
- 每次 `aa` 初始化或变化时，调用 `comp_max7219_show_fixed1(aa×10)`，四位数码管显示一位小数。
- PA11/P5-14/TIM1_CH4 输出 500Hz 硬件 PWM；PB14 上的 LED1 使用同一目标占空比的软件 PWM，形成约 2 秒一次的亮灭呼吸。
- 为保留原题行为，上电 30 秒灯控和按键1流水灯期间暂停呼吸；对应灯控完成、进入空闲状态后自动呼吸。

**数码管硬件限制：**现有驱动针对 `MAX7219 + FJ5463A 四位共阴数码管`，并要求 PB12、PA2、PE0 三根控制线经过 5V 供电的 74AHCT125 电平转换。此前照片中的 MAX7219 8×8 点阵模块不能直接使用这套四位数码管驱动显示 `aa`。

## 五、现场最常改的函数和参数

| 函数/宏 | 参数含义 | 现场怎么改 |
|---|---|---|
| `EXAM2025_STARTUP_LED_TIME_MS` | 上电灯 1、3 保持时间，毫秒 | 30 秒改为 10 秒：写 `10000UL` |
| `EXAM2025_LED_STEP_TIME_MS` | 流水灯每一步间隔，毫秒 | 更快可改为 `200UL` |
| `exam2025_start_led_sequence(step_time_ms)` | 启动“先全灭，再 1~4 累加点亮”；参数是每步毫秒数 | 新题要求 1 秒一步：传 `1000U` |
| `comp_led_set_mask(mask)` | bit0~bit3 分别控制 LED1~LED4，1=亮 | 只亮 2、4：传 `0x0A` |
| `exam2025_uart_send_line(text)` | 发送 ASCII 字符串并自动补 `\r\n` | 发送 OK：`exam2025_uart_send_line("OK")` |
| `exam2025_set_aa_tenths(value, save, send)` | `value` 是真实值×10；`save=1` 写存储；`send=1` 发串口 | 设为 12.5 并保存发送：`exam2025_set_aa_tenths(125, 1, 1)` |
| `exam2025_get_aa_tenths()` | 返回当前 `aa×10` | 返回 15 代表 1.5 |
| `comp_hanzi_show_utf8(x,y,text,fg,bg)` | 坐标、UTF-8 文本、前景色、背景色 | 显示“比赛”：传 `COMP_TEXT_COMPETITION` |
| `comp_keys_poll_event()` | 返回一次消抖后的按下事件 | 返回值见下表 |
| `comp_keys_read_mask()` | 读取四键稳定电平掩码 | 判断松开/长按时使用 |

按键枚举：`COMP_KEY_BOARD_0`=按键1，`COMP_KEY_BOARD_1`=按键2，`COMP_KEY_EXT_0`=按键3，`COMP_KEY_EXT_1`=按键4。

## 六、汉字字库

字库是 **16×16 点阵 UTF-8 子集**，共 76 个汉字，不是整套中文字库。已经覆盖：

> 测评题、发送成功、比赛、赛道、嵌入式、芯片、系统、设计、点亮、赋能、全国大学生、电子信息、工程、技术、创新、作品、功能、按键、串口、上位机、下位机、数据、存储、读取、写入、失败、开始、停止、增加、减少、数值、电源、初始化、当前、状态、等待、完成。

常用短语已经在 `comp_hanzi.h` 中做成 `COMP_TEXT_...` 宏，可直接传给 `comp_hanzi_show_utf8()`。未收录汉字不会乱码，而是显示方框，提醒现场补字模。

## 七、建议的实物验收顺序

1. 先只接开发板、DAP、USB_UART 和 TFTLCD，下载后确认显示 `st测评题` 和 `aa = 0.0`（或上次保存值）。
2. 串口助手选 115200、8N1，发送 `st`，确认收到 `st is ok`。
3. 焊接并核对外接 LED/按键洞洞板后再上电；LED 每路必须串限流电阻，按键接到 GND，不能把 GPIO 直接短接电源。
4. 验证上电灯 1、3 点亮，30 秒后全亮。
5. 按下并松开板载按键 1，观察先全灭再依次累加点亮。
6. 按板载按键 2，串口收到 `key2`，屏幕显示“发送成功”。
7. 按外接按键 3/4，观察 `aa` 每次变化 0.5 且串口同步输出；断电重启检查数值恢复。
