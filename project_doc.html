项目简介

NECCS 是一款嵌入式实时声学相机系统，能够实时确定声源在空间中的方位角（水平角和垂直角）， 并以热力图的形式显示在 800×480 RGB LCD 屏幕上。

功能特性

  • 16 路麦克风同步采集
  • SRP-PHAT 声源定位
  • ±60° 水平 + 垂直定位
  • 30 FPS 热力图实时显示
  • VOFA+ 实时调试输出
  • 运行时 CLI 参数调整

关键性能

  • 采样率：48 kHz / 16 bit
  • 帧长：256 点（5.33 ms/帧）
  • 算法延迟：~5 ms/帧
  • 定位精度：±5°（精搜后）
  • 频率范围：562 Hz ~ 7.9 kHz
  • 麦克风对数：40 对

开发环境

  • IDE：Keil MDK (AC5)
  • HAL 库：STM32H7xx HAL
  • RTOS：FreeRTOS v10
  • DSP：CMSIS-DSP v1.9
  • 调试：VOFA+ 上位机
  • LUT 生成：Python 3

内存布局

STM32H743 具有多个内存区域，各有不同的访问速度和缓存特性。 本项目根据数据访问模式将缓冲区精心分配到合适区域，最大化性能。

0x30000000 SRAM1（16 KB） Non-Cacheable（MPU 配置）— DMA 安全区，CPU 读取保证数据最新
Mic_Rx_Buffer SAI DMA 接收区，16384 字节（PING 8192 B + PONG 8192 B）
0x20000000 DTCM（128 KB） 零等待（紧耦合到 Cortex-M7）— CPU 密集计算区，无缓存延迟
Mic_Process_Buffer 解交织后时域 float32，16 × 256 × 4 B = 16 KB
Mic_Freq_Buffer FFT 频域复数 float32，16 × 256 × 4 B = 16 KB
Hanning_Window 汉宁窗系数，256 × 4 B = 1 KB
S_Rfft RFFT 实例（含旋转因子表），频繁访问，零等待至关重要
0x24000000 AXI SRAM（512 KB） Cacheable — 大容量中间结果，顺序访问缓存命中率高
GCC_PHAT_Buffer GCC-PHAT 白化互相关，40 对 × 40 bins × 2（复数）× 4 B ≈ 12.8 KB
SRP_Power SRP 功率网格，129 点 × 4 B ≈ 516 B
0xC0000000 SDRAM（32 MB） Cacheable — 帧缓冲区（LTDC 双缓冲）
Frame Buffer × 2 RGB565，800 × 480 × 2 B × 2 帧 = 1.5 MB
为什么 DMA 缓冲区必须在 Non-Cacheable 区？
Cortex-M7 的数据缓存（D-Cache）对 DMA 写入是透明的——DMA 直接写入物理内存， 但 CPU 可能从缓存中读到旧数据。将 DMA 目标区域配置为 Non-Cacheable， CPU 每次都从物理内存读取，保证数据一致性，无需手动 SCB_InvalidateDCache。

麦克风阵列

物理布局（4×4 URA）

/* 坐标系（正面看向声学相机）：
 *   +X 轴：向右
 *   +Y 轴：向上
 *   +Z 轴：向前（垂直阵列平面，声源方向）
 *
 * 麦克风编号布局（示意，实际间距由阵列设计决定）：
 *   [12][13][14][15]   ← 顶行（Y 最大）
 *   [ 8][ 9][10][11]
 *   [ 4][ 5][ 6][ 7]
 *   [ 0][ 1][ 2][ 3]   ← 底行（Y 最小）
 *
 * 麦克风间距约束：
 *   最小半波长间距 = c / (2 × f_max) = 343 / (2 × 7875) ≈ 2.18 cm
 *   间距过大会导致空间混叠（相位模糊），间距过小降低分辨率
 */

麦克风对选择策略

从 16 个麦克风的 C(16,2) = 120 个可能对中， 按基线长度降序选择 40 对。 长基线对方向分辨率高但易产生空间模糊，短基线对消除模糊但分辨率低， 两者组合使用可兼顾精度和鲁棒性。

PCMD3180 驱动

芯片特性

  • 8 路 PDM 输入（支持 4 个立体声 MEMS 麦克风）
  • TDM 输出，支持 16/24/32 bit，最多 16 时隙
  • 片上可配置 HPF（高通滤波器），去除直流和低频噪声
  • I²C 控制接口，7-bit 地址（A0/A1 引脚配置）
  • Slave 模式：BCLK 和 FSYNC 由外部 SAI 提供

完整初始化序列

/* PCMD3180_Init_Device(devAddr, startSlot) 完整流程 */

PCMD_Ctrl_Reset(devAddr);             // 1. 写 0x01 到 REG_SW_RESET → 软复位
vTaskDelay(10);                        // 2. 等待 10ms，PLL 和内部电路稳定
PCMD_Ctrl_Sleep(devAddr, 1);           // 3. 进入 Sleep（写 REG_SLEEP_CFG=0x02）
                                         //    注意：寄存器配置必须在 Sleep 中进行！
PCMD_Config_ASI_Format(devAddr);      // 4. ASI：TDM16 格式 / 16bit / Offset=1
PCMD_Config_TDM_Slots(devAddr, startSlot); // 5. 分配 8 个连续 TDM 时隙（0 或 8）
PCMD_Config_PDM_IO(devAddr);          // 6. PDM 时钟 64× OSR，GPO1 输出 PDM CLK
PCMD_Config_DSP(devAddr);             // 7. 启用 HPF（高通滤波，截止频率约 20 Hz）
PCMD_Config_Channels(devAddr);        // 8. 8 路输入全部配置为 PDM 模式
PCMD_Config_Clock_Mode(devAddr);      // 9. Slave 模式，时钟源 = BCLK（由 SAI 提供）
PCMD_Enable_Blocks(devAddr);          // 10. 使能：输入通道 + ASI 输出 + PLL + ADC
PCMD_Ctrl_Sleep(devAddr, 0);          // 11. 退出 Sleep，进入 Active 状态
vTaskDelay(10);                        // 12. 等待上电稳定
PCMD_Check_Health(devAddr);           // 13. 读 REG_DEV_STS0/1，检查 PLL 锁定和 ASI 状态
重要：PCMD3180 寄存器配置必须在 Sleep 模式下进行。 若在 Active 状态写入配置寄存器，配置可能不会生效，导致 TDM 时隙错乱或采样率错误。

SAI + DMA 双缓冲

PING/PONG 双缓冲机制

DMA 以循环（Circular）模式持续将 TDM 数据写入 Mic_Rx_Buffer。 缓冲区分为 PING（前半）和 PONG（后半）两个区域，DMA 和 CPU 始终操作不同半区。 

/* 时序示意（每 5.33ms 一帧）：
 *
 * DMA：  ←── 写 PING ───→ ←── 写 PONG ───→ ←── 写 PING ───→ ...
 * ISR：                  ↑HalfCplt          ↑CpltCallback
 *             （PONG 可读）                  （PING 可读）
 * CPU：       [处理 PONG]                   [处理 PING]
 *                         [处理 PING]
 *
 * Mic_Rx_Buffer 布局：
 *   [0      .. 8191 ]  = PING 区（前半）→ DMA Half Complete 时已就绪
 *   [8192   .. 16383]  = PONG 区（后半）→ DMA Full Complete 时已就绪
 *
 * 每半区包含：16 通道 × 256 采样 × 2 字节 = 8192 字节（1 帧）
 */

DMA 中断回调

回调触发时机推送事件
HAL_SAI_RxHalfCpltCallback DMA 写完 PING 区（前半完成） 推送 AUDIO_DMA_HALF_PING 到 xAudioFrameQueue
HAL_SAI_RxCpltCallback DMA 写完 PONG 区（循环一圈） 推送 AUDIO_DMA_HALF_PONG 到 xAudioFrameQueue

每个事件携带单调递增的 seq 字段。音频任务对比收到的 seq 与 上次 seq，若差值 > 1，说明发生了丢帧（队列覆盖）。 丢帧次数通过 g_audio_frame_seq_isr 可在调试时监控。

数据预处理（解交织）

问题描述

SAI DMA 收到的 TDM 数据按时间交织：同一时刻所有通道的采样值连续排列。 FFT 处理需要每个通道连续的时间序列（平面格式），需要做格式转换。

矩阵转置方法

将交织数据视为 256行 × 16列 的矩阵（行=时刻，列=通道）， 转置后得到 16行 × 256列 的矩阵（行=通道，列=时刻）， 即所需的平面格式。 使用 CMSIS-DSP 的 arm_mat_trans_q15，底层通过 SIMD 指令 VTRN/VZIP 并行处理，速度比手写循环快约 4 倍。 

/* Deinterleave_Using_Matrix 实现 */
arm_matrix_instance_q15 mat_src, mat_dst;

/* 源矩阵：256 行 × 16 列（交织，每行是一个时刻的所有通道采样）*/
arm_mat_init_q15(&mat_src, frame_size, num_channels, src_interleaved_q15);

/* 目标矩阵：16 行 × 256 列（平面，每行是一个通道的全部采样）*/
arm_mat_init_q15(&mat_dst, num_channels, frame_size, dst_planar_q15);

arm_mat_trans_q15(&mat_src, &mat_dst);  // SIMD 转置，~0.15 ms

/* q15 → float32：val / 32768.0，归一化到 [-1.0, 1.0]
 * 使用 SIMD VCVT 指令，~0.15 ms */
arm_q15_to_float(dst_planar_q15, dst_planar_f32, frame_size * num_channels);

FFT 频域变换

AI_FFT_Process() 流程

对 16 路信号分别执行去直流、加窗、256 点实数 FFT，共约 0.8 ms。

for (uint32_t ch = 0; ch < MIC_CHANNELS; ch++) {
    float32_t *in  = Mic_Process_Buffer + ch * FRAME_LEN;
    float32_t *out = Mic_Freq_Buffer    + ch * FRAME_LEN;

    /* 步骤 1: 去直流（DC offset removal）
     * 消除麦克风偏置，避免 DC 分量污染低频 bin
     * arm_mean_f32: 计算均值（SIMD 累加）
     * arm_offset_f32: 整体减去均值（SIMD 减法） */
    float32_t mean;
    arm_mean_f32(in, FRAME_LEN, &mean);
    arm_offset_f32(in, -mean, in, FRAME_LEN);

    /* 步骤 2: Hanning 窗（频谱泄漏抑制）
     * w[n] = 0.5 × (1 - cos(2πn/N))，n = 0..255
     * 作用：使信号两端平滑过渡到 0，减少截断效应
     * arm_mult_f32: 逐点乘法（SIMD 向量乘）*/
    arm_mult_f32(in, Hanning_Window, in, FRAME_LEN);

    /* 步骤 3: 256 点实数 FFT（RFFT）
     * 输出为 packed 格式，256 个 float32：
     *   [0]       DC 实部
     *   [1]       奈奎斯特（24 kHz）实部
     *   [2k]      bin k 实部  （k=1..127，频率 k×187.5 Hz）
     *   [2k+1]    bin k 虚部
     * ifftFlag=0 表示正向 FFT（时域→频域）*/
    arm_rfft_fast_f32(&S_Rfft, in, out, 0);
}

GCC-PHAT 广义互相关

算法原理

GCC-PHAT（Generalized Cross-Correlation with Phase Transform） 通过计算两路麦克风信号的互相关，估计声音到达两个麦克风的时延差（TDOA）。 PHAT 白化操作将互相关谱归一化为单位幅度，保留纯相位信息， 这使得算法对混响和宽带噪声具有较强的鲁棒性。 

/* 对每对麦克风 (i, j)，在 SRP 频率范围（bin 3~42）内计算 GCC-PHAT */

for (uint32_t k = SRP_FREQ_BIN_START; k <= SRP_FREQ_BIN_END; k++) {

    /* 取通道 i 在 bin k 处的复数频谱：X_i = Re_i + j×Im_i */
    float32_t Re_i = Mic_Freq_Buffer[i * FRAME_LEN + 2*k    ];
    float32_t Im_i = Mic_Freq_Buffer[i * FRAME_LEN + 2*k + 1];
    float32_t Re_j = Mic_Freq_Buffer[j * FRAME_LEN + 2*k    ];
    float32_t Im_j = Mic_Freq_Buffer[j * FRAME_LEN + 2*k + 1];

    /* 步骤 1: 交叉功率谱 G = X_i × conj(X_j)
     * Re_G = Re_i×Re_j + Im_i×Im_j
     * Im_G = Im_i×Re_j - Re_i×Im_j  */
    float32_t Re_G = Re_i * Re_j + Im_i * Im_j;
    float32_t Im_G = Im_i * Re_j - Re_i * Im_j;

    /* 步骤 2: PHAT 白化 — 除以幅度，保留相位
     * |G| = sqrt(Re_G² + Im_G²)
     * G_phat = G / (|G| + ε)   ← ε 防止除零 */
    float32_t mag = sqrtf(Re_G*Re_G + Im_G*Im_G) + PHAT_EPSILON;
    GCC_PHAT_Buffer[pair][k - SRP_FREQ_BIN_START][0] = Re_G / mag;
    GCC_PHAT_Buffer[pair][k - SRP_FREQ_BIN_START][1] = Im_G / mag;
}

SRP 可控响应功率

核心公式

对候选方向 (θ, φ)，预期时延差为： τ = (dx × sin(θ) × cos(φ) + dy × sin(φ)) / c

该方向的 SRP 功率（所有麦克风对、所有频率 bin 的贡献之和）： 

/* SRP_Accumulate_Point(theta_deg, phi_deg) 伪代码 */

float32_t power = 0.0f;

for (uint32_t p = 0; p < SRP_PAIR_COUNT; p++) {

    /* 根据麦克风对位移和候选方向计算 TDOA（单位：秒）*/
    float32_t tau = (srp_pair_dx[p] * sinf(theta) * cosf(phi)
                   + srp_pair_dy[p] * sinf(phi)) / SPEED_OF_SOUND;

    /* 相位递推初始化（起始 bin = SRP_FREQ_BIN_START）
     * 相位增量：Δφ = 2π × Δf × tau（相邻 bin 之间固定）
     * 只需在循环开始时计算 4 次三角函数，之后递推 */
    float32_t phi0    = 2.0f * PI * SRP_FREQ_BIN_START * DELTA_F * tau;
    float32_t dphi    = 2.0f * PI * DELTA_F * tau;
    float32_t cos_phi = cosf(phi0), sin_phi = sinf(phi0);
    float32_t cos_dp  = cosf(dphi), sin_dp  = sinf(dphi);

    for (uint32_t k = 0; k < SRP_FREQ_BINS; k++) {
        /* GCC-PHAT 贡献：Re_phat × cos(φ_k) + Im_phat × sin(φ_k)
         * 等价于取复数乘积的实部 */
        power += GCC_PHAT_Buffer[p][k][0] * cos_phi
               + GCC_PHAT_Buffer[p][k][1] * sin_phi;

        /* 相位递推（利用和角公式，避免重复 cos/sin 调用）*/
        float32_t new_cos = cos_phi * cos_dp - sin_phi * sin_dp;
        float32_t new_sin = sin_phi * cos_dp + cos_phi * sin_dp;
        cos_phi = new_cos; sin_phi = new_sin;
    }
}
return power;  // 越大说明声源越可能在 (theta, phi) 方向

粗搜 + 精搜两级策略

粗搜（Coarse Scan）

  • 网格：9 × 9 = 81 个扫描点
  • 角度范围：水平 ±60°，垂直 ±60°
  • 步长：15°/点（每维度）
  • TDOA：直接查 Flash LUT，无需实时计算
  • 耗时：~2 ms（含 LUT 查表 + 40 对相位累加）

精搜（Fine Scan）

  • 对粗搜结果 Top-3 峰值（NMS 过滤邻近峰）
  • 每峰值周围 4 × 4 = 16 个扫描点
  • 总计：3 × 16 = 48 个扫描点
  • 每峰值范围：±10°，步长 5°
  • TDOA：实时计算（精搜角度不规则，无法预表格）
  • 耗时：~1 ms

Top-K NMS 选峰算法

粗搜 81 个点中选出 3 个分散的峰值，用于精搜。 使用非极大值抑制（NMS）避免选到相邻的旁瓣：

  1. 按 SRP 功率降序排列 81 个粗搜点
  2. 从最大值开始，逐个检查候选点
  3. 若候选点与已选峰值的网格曼哈顿距离 ≤ SRP_TOPK_NMS_RADIUS（=1），则跳过
  4. 直到选出 3 个相互分散的峰值为止

预计算查找表（LUT）

粗搜的 TDOA 值（81 个扫描点 × 40 对麦克风）在编译前由 Python 脚本预计算， 以 const float32_t 数组的形式存入 Flash，约 13 KB。 运行时直接查表，无需执行三角函数，极大加快粗搜速度。

数据维度大小说明
srp_pair_idx[40][2]80 B40 对麦克风的通道索引 (i, j)
srp_pair_dx[40]160 BX 方向位移（米），用于精搜实时计算
srp_pair_dy[40]160 BY 方向位移（米），用于精搜实时计算
coarse_theta_deg[9]36 B粗搜水平角度表（-60° 到 +60°，步长 15°）
coarse_phi_deg[9]36 B粗搜垂直角度表（-60° 到 +60°，步长 15°）

质量评估与置信度

三个质量指标

指标计算公式物理意义阈值
对比度 (contrast) (P_max - P_second) / P_max 主峰突出程度。值越小，声场越模糊（多声源或强混响） ≥ 0.03
质量 (quality) (P_max - P_far_second) / P_max 排除 ±5° 旁瓣后的对比度，更严格的单声源判断 ≥ 0.01
能量 (energy) P_max / P_reference 归一化声源能量，低值可能表示无声源或信噪比差 ≥ 0.05

低置信度策略（可在 ai_config.h 配置）

策略宏行为适用场景
SRP_LOWCONF_REPORT_NEW（默认） 始终输出最新结果，无论置信度 实时响应优先，允许抖动
SRP_LOWCONF_HOLD_LAST 置信度低时保持上次有效结果 需要稳定输出（如控制系统）
SRP_LOWCONF_MIXED 保持 N 帧后接受新结果（N 由 HOLD_FRAMES 配置） 平衡稳定性与响应速度

LTDC 双缓冲

系统使用双帧缓冲技术消除显示撕裂。 两个帧缓冲均位于 SDRAM（每个 800×480×2=768 KB，RGB565 格式）：

  • 前缓冲（Front Buffer）：LTDC 正在扫描并输出到 LCD
  • 后缓冲（Back Buffer）：CPU 和 DMA2D 正在渲染下一帧

渲染完成后调用 ltdc_request_swap() 设置换页请求标志。 LTDC 在下一个垂直消隐期（VSYNC）的中断回调中切换图层地址， 保证换页发生在非显示期间，LCD 上完全无撕裂。

DMA2D 图形加速

STM32H7 内置 DMA2D（Chrom-Art Accelerator）是专用的图形像素搬运引擎， 可在 CPU 处理算法的同时异步搬运像素数据，大幅降低显示对 CPU 的占用。

操作API 函数典型用途
矩形单色填充ltdc_fill_async清屏、绘制背景色块
RGB565 位块传输ltdc_color_fill_async将渲染好的热力图像素写入帧缓冲
L8 调色板格式转换ltdc_l8_fill_async8 位热力图索引 → RGB565 输出（最高效）
A8 透明度混合ltdc_a8_blend_async文字、图标与背景的 Alpha 混合
等待传输完成ltdc_draw_flush同步点，带超时保护（防止死锁）
降级保护：当 DMA2D 超时或硬件故障时，系统自动回退到 CPU 软件填充路径（sw_fallback）。 超时次数通过 g_ltdc_dma2d_timeout_count 实时统计，可在调试时监控硬件健康状态。

性能指标

各阶段耗时（@ 480 MHz Cortex-M7，16ch × 256 点）

① 解交织（矩阵转置 + q15→float32）~0.3 ms
② FFT × 16 通道（去直流 + 加窗 + RFFT）~0.8 ms
③ GCC-PHAT（40 对 × 40 bins）~1.0 ms
④ SRP 粗搜（81 点 LUT 查表）~2.0 ms
⑤ SRP 精搜（48 点实时计算）~1.0 ms
总音频流水线~5.1 ms（帧预算 5.33 ms，余量 4.9%）

内存使用汇总

  • SRAM1（DMA 缓冲）：16 KB
  • DTCM（算法缓冲）：约 34 KB
  • AXI SRAM（中间结果）：约 14 KB
  • Flash（LUT + 代码）：LUT 约 13 KB
  • SDRAM（帧缓冲双缓冲）：1.5 MB

实时性保障机制

  • 帧周期：5.33 ms（256点/48kHz）
  • ISR 到任务唤醒：<1 µs
  • RTOS：抢占式调度，优先级 4
  • 丢帧策略：队列覆盖（不积压）
  • UI 刷新：33 ms（30 FPS）
性能裕量警示：音频流水线耗时约占帧预算的 96%，裕量极小。 若需提高扫描精度（更大 COARSE_GRID_SIZE 或更多 SRP_PAIR_COUNT）， 建议先通过 decim N 命令将算法调用频率降低到每 N 帧一次， 再评估性能裕量。
